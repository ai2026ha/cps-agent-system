- 不修改数据库结构，无需重建 PostgreSQL。

# CPS 智能代理系统 V71

V71 新增正式特权卡与超级管理员玩家行为测试。

- 特权卡支持周卡（7天）、月卡（30天）、年卡（365天）。
- 超管可配置特权卡名称、平台币售价、每日奖励内容与启用状态。
- 玩家必须先选择区服/角色购买特权卡；购买真实扣除平台币，并绑定角色。
- 每张生效中的特权卡每天仅可领取一次奖励；同一种卡续购自动顺延周期，避免同日重复领取。
- 特权卡购买不计真实流水、不产生代理佣金，也不增加礼包商城累充进度。
- 超管新增“玩家行为测试”，可按玩家账号/玩家ID/角色名/区服搜索角色，并真实模拟礼包购买、特权卡购买和累充领取。测试操作写入真实业务数据库，请只用于测试玩家。
- Render/PostgreSQL 升级无需删库，新表由启动时 `Base.metadata.create_all()` 自动创建。

# CPS 智能代理系统 — V68

V68 修复登录首屏体验与默认凭据暴露问题。

## V68 更新

- 后台和玩家中心刷新时先静默恢复登录状态，不再先显示登录页再跳转。
- 有有效登录令牌时直接恢复已登录页面；令牌失效时才显示登录页。
- 后台登录账号/密码不再硬编码 `admin / ChangeMe123!`，输入框默认保持空白。
- 登录表单关闭默认自动填充提示，降低浏览器自动填充旧凭据的概率（浏览器/密码管理器仍可能按用户自身设置填充已保存凭据）。
- 不修改数据库结构，无需重建 PostgreSQL。

## V67 及既有功能
CDK 兑换角色/区服绑定等 V67 功能继续保留。

## V67 更新

- 玩家中心进入“CDK兑换”后，必须先选择当前账号下的区服 / 角色，再输入 CDK。
- 后端强制校验所选 `character_id` 必须属于当前登录玩家，不能通过接口伪造其他玩家角色。
- CDK 兑换成功时在 `redemption_codes` 中保存：`player_id`、`character_id`、`role_name`、`server_name`、`redeemed_at`。
- `role_name` / `server_name` 保存兑换时快照，后续角色改名或转服不会改写历史兑换归属。
- 历史已兑换 CDK 因没有可靠角色证据，不猜测、不自动回填角色。
- Render 启动时自动补充 `redemption_codes.character_id / role_name / server_name` 字段，无需删除 PostgreSQL。

## 当前玩家中心规则

- 纯手机端玩家中心。
- 功能顺序：平台币充值 → 购买礼包 → 领取累充 → 特权卡 → CDK兑换。
- 商城购买按所选区服角色记录订单。
- 真实平台币充值只计真实流水和代理分佣，不增加累充。
- 手工发放/收回平台币只调整余额，不计流水、分佣、累充。
- 角色购买网页礼包实际消耗的平台币，计入该角色当日累充和永久累充，不计真实流水与分佣。
- 领取累充时先选择区服角色，显示该角色当日累充与永久累充，再返回该角色可领取奖励。
- CDK兑换时先选择区服角色，兑换记录绑定该角色。
